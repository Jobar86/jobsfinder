# QA Job Tracker Dashboard

Visual dashboard to track manual QA job applications. Runs locally — your data stays on your machine.

## What it does

- Lists all QA jobs found by the scanner in a filterable table
- Track status per job: Interested / Applied / Interview / Offer / Rejected / Skip / Dead
- Add notes per job
- Filter by region (LATAM / Worldwide), portal, status
- Sort by date found, company, or status
- Kanban view
- Auto-detects expired postings (liveness check)

---

## Prerequisites

- Node.js 18+
- career-ops set up (see main README)

---

## Quick Start

### 1. Run a scan to populate jobs

```bash
# Inside Claude Code
/career-ops scan
```

This creates `reports/manual-qa-jobs-YYYY-MM-DD.md` with jobs found.

### 2. Start the dashboard server

```bash
node dashboard-server.mjs
```

Server runs at `http://localhost:4242`. Keep this terminal open.

### 3. Open in browser

Navigate to: **http://localhost:4242**

You should see your jobs loaded with `🟢 Live` badge in the header.

## Files

| File | Purpose |
|------|---------|
| `dashboard-server.mjs` | Node.js server (port 4242). Parses `manual-qa-jobs-*.md` and serves JSON |
| `reports/dashboard.html` | Dashboard UI (served by the server) |
| `parse-liveness.mjs` | Converts liveness check log → `dead-jobs.json` |
| `reports/manual-qa-jobs-*.md` | Job list generated by scanner (gitignored, your data) |
| `reports/dead-jobs.json` | Expired job IDs (gitignored, auto-generated) |

---

## Updating Jobs (run a new scan)

```bash
/career-ops scan
```

New jobs append to the existing `manual-qa-jobs-*.md` file and appear in the dashboard on next reload. No data loss — your saved statuses and notes are stored in browser localStorage.

## Checking for expired postings

Run a liveness check on all your current job URLs, then parse the results:

```bash
# Extract URLs from your job file
grep -oP 'https?://[^\)]+' reports/manual-qa-jobs-*.md > reports/urls-to-check.txt

# Run liveness check (uses Playwright — takes ~20-30 min for 100+ URLs)
node check-liveness.mjs --file reports/urls-to-check.txt | tee reports/liveness-$(date +%Y-%m-%d).log

# Parse results → dead-jobs.json
node parse-liveness.mjs reports/liveness-$(date +%Y-%m-%d).log
```

Reload the dashboard — jobs confirmed expired will be auto-marked as 💀 Dead (only if you haven't already set their status manually).

## Status Reference

| Status | Meaning |
|--------|---------|
| 👀 Interested | Not yet applied, worth looking at |
| 📤 Applied | Application sent |
| 🎤 Interview | In interview process |
| 🎉 Offer | Offer received |
| ❌ Rejected | Rejected |
| 🚫 Skip | Not interested, skipping |
| 💀 Dead/404 | Posting expired or URL broken |

Statuses are saved in browser localStorage — they persist across server restarts and page reloads.

## Customizing the scanner (portals.yml)

`portals.yml` controls what roles the scanner looks for. Key settings:

```yaml
title_filter:
  positive:
    - QA
    - Quality Assurance
    - Tester
  negative:
    - Automation Engineer   # exclude SDET roles
    - Junior
    - Embedded
```

Edit `positive` keywords to match your target roles, `negative` to filter out noise.

## Troubleshooting

**Dashboard shows `🟡 Offline`**
→ Server not running. Run `node dashboard-server.mjs`.

**No jobs appear**
→ No `manual-qa-jobs-*.md` in `reports/`. Run `/career-ops scan` first.

**Status reset after reload**
→ Statuses live in browser localStorage for `http://localhost:4242`. Don't clear browser data for localhost.

**Port 4242 already in use**
→ Another server instance is running. Kill it: `pkill -f dashboard-server.mjs`
